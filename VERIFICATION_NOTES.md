# Verification Notes

## Masking

- **Joint traces, not marginal observations.** [MaskingTrace.joint_trace_distribution](masking/trace_masking.v) proves composition when every hidden state gives the same next-observation distribution. Fresh post-operation Y observations satisfy this contract; arbitrary internal observations do not.
- **Instrument the existing computation.** [LadderTrace.program_erasure](masking/ladder_trace.v) proves that removing recorded checkpoints recovers the original shared program, rather than replacing it with an independent simulation.
- **Curve25519 checkpoint theorem.** [MaskedCurve25519.correct_and_checkpoint_independent](masking/masked_curve25519.v) proves correct reconstruction and equal joint checkpoint distributions for any public curve point and any two scalars in the public width.
- **Exact observations.** One refreshed four-coordinate Y vector after each complete LadderStep, followed by final affine Y. Initial state, individual field operations, swaps/control, masks, the other shares, and affine intermediates are excluded. This is not a processor power-trace theorem.
- **Stronger claims fail.** [LeakageCounterexamples](masking/leakage_counterexamples.v) checks one-bit combined-share HW and multiplication/squaring intermediates. Its temporal example proves that uniform marginals can still have secret-dependent joint distributions. Arithmetic examples are exhaustive counts over uniform masks; the temporal example uses Infotheo distributions directly.

## Quartz Accelerator

- **Actual DSL arithmetic.** [AcceleratorCorrectness.reduce_correct](quartz/accelerator_correctness.v) covers every 512-bit input. Three folds preserve the residue and put it below twice the prime, so one subtraction suffices. [arithmetic_correct](quartz/accelerator_correctness.v) handles every pair of 255-bit operands, including noncanonical encodings.
- **Complete LadderStep.** [AcceleratorLadderBridge.ladder_step_matches_math](quartz/accelerator_ladder_bridge.v) proves that the actual 18-tick execution implements the existing mathematical LadderStep for canonical field inputs. It is not a full scalar-loop theorem.
- **No security inference from timing.** [LadderAcceleratorLeakage.initial_bank_HW_distinguishes](quartz/accelerator_leakage.v) gives two canonical coordinate inputs with the same control state but different total HW across all 32 stored 255-bit words. These are accelerator inputs, not a proved pair of full scalar executions. Combinational leakage is outside this observation.
- **Selected protection target: aggregate register HW.** [ProtectedAccelerator](quartz/protected_accelerator.v) stores a complementary bank alongside the actual DSL core and updates both in one transition. Initialization, start, reset, and ticks establish or preserve pairing; erasure recovers the original core computation.
- **Protected LadderStep contract.** [ProtectedAcceleratorSecurity.ladder_step_correct_and_secure](quartz/protected_accelerator_security.v) combines mathematical LadderStep correctness with equal register-HW traces. Both banks contribute exactly 8160; the unpaired phase register is included and must start equal across runs. Traces include the valid initial state and all subsequent tick boundaries.
- **Native CPU integration.** [QuartzAcceleratorCPUSecurity.device_bank_HW_constant](quartz/accelerator_cpu_security.v) proves that the existing CPU/MMIO adapter preserves the protected device bank during arbitrary runs. This is only a device-bank property, not a theorem about the CPU registers, staging RAM, or response buffers.

## Common Noisy-Leakage Target

The shared target is functional correctness and a quantitative bound on leakage, not perfect independence for both implementations. For implementation `I`, fixed public inputs, public execution length `T`, and `q` independent executions, require `TV(law(Traces_I(k1)), law(Traces_I(k2))) <= epsilon_I` for any two allowed secrets. `TV` is half the L1 distance; Infotheo's `var_dist` uses the unhalved convention. A useful claim must give an explicit bound below 1 for a stated budget.

- **Common observer:** initially, equally weighted aggregate stored-register HW at public clock boundaries, followed by the same secret-independent noise channel. Include initialization and all scheduled intermediate observations. Do not replace the full trace with refreshed-Y checkpoints.
- **First noise instance:** the sum of two independent fair bits, added without modular wraparound. This small binomial channel has probabilities `1/4, 1/2, 1/4` and permits exact checks in Infotheo. It is not a calibrated physical channel or a Gaussian-noise theorem. General results should parameterize the channel rather than hard-code this example.
- **Composition:** retain correlations within an execution. Repeated-execution bounds initially assume fresh masks and noise and the same fixed public input on each run. Adaptive chosen-input attacks, persistent randomness, and correlated physical noise require separate treatment.
- **Correctness and release:** prove the decoded output equals the Curve25519 specification. The first leakage contract excludes the external output-release event, not output-bearing registers or reconstruction performed during observed cycles. It does not claim secrecy of the full attacker view containing the released output. Output-conditioned security requires an explicit release policy.
- **Fair comparison:** fix the observer, noise parameters, and budget across implementations. Their numeric traces and achieved bounds need not coincide. Do not add complementary storage to masking merely to reuse the dual-storage proof.

The development proceeds from encoding bounds through whole-bank refresh to actual Quartz execution. The complete masked-controller results and remaining verification gates are recorded below. Encoding results alone are not secure multiplication gadgets.

Checked foundation: [NoisyLeakage.channel_TV_contraction](masking/noisy_leakage.v) proves that a common finite channel cannot increase total variation; [constant_observation_noisy_equal](masking/noisy_leakage.v) preserves exact independence of constant observations. [iid_TV_bound](masking/noisy_leakage.v) bounds `q` independent executions by `q` times the one-execution distance; [TV_at_most_one](masking/noisy_leakage.v) supplies the universal cap. These lemmas do not supply a small masked-circuit bound by themselves.

Checked single-observation example: [NoisyBitExample](masking/noisy_bit_example.v) uses the same binomial channel for plain, XOR-shared, and complementary encodings. `plain_TV`, `masked_TV`, and `dual_TV` give exact distances `1/2`, `1/4`, and `0`. Reconstruction and nonwrapping noise addition are proved; `masked_laws_distinct` retains the residual-leakage result. [masked_all_secrets_budget](masking/noisy_tests.v) gives the upper bound `q/4` for any two secret bits with fresh randomness per repetition. These are encoding results, not circuit-execution results.

## Parameterized Bounds

Use `n = d+1` total XOR shares; the code parameter `d` counts extra shares. [XorShares.share_correct](masking/xor_shares.v) proves reconstruction for every positive share count. [NoisyShares.sample_shares](masking/noisy_shares.v) and `sample_observations` identify both marginals of the joint share/observation sampling, rather than replacing the encoded secret with an unrelated random value.

[NoisyChannelBridge.aggregate_as_HW_channel](masking/noisy_channel_bridge.v) proves exact equality to raw aggregate share HW followed by independent additive binomial noise. Its clipping bounds justify ordinary addition. `dual_law` uses the identical scalar channel, noise count, and output bound; `dual_laws_equal` proves exact independence. The noise bits describe the measurement channel, not an on-chip noise generator or the mask RNG.

- [NoisyShares.fine_TV](masking/noisy_shares.v): exact TV `2^-n` when each share is separately observed with one independent fair noise bit.
- [NoisyShares.aggregate_TV_bound](masking/noisy_shares.v): aggregate observation has TV at most `2^-n`, with `n+e` fair noise bits for any extra count `e`. Addition is nonwrapping. Summation discards information, so the aggregate result is an upper bound, not an equality claim.
- [NoisyWords](masking/noisy_words.v): independently encode every bit of a `w`-bit word. The snapshot bound is `w * 2^-n`, including a 255-bit specialization; the concrete aggregate channel uses `w*n+e` independent fair noise bits.
- [NoisyTrace](masking/noisy_trace.v): if every modeled step's observation law is within `epsilon` of a shared public per-step reference for every hidden state, a `T`-step trace is within `T*epsilon` of the reference trace. Two initial states are within `2*T*epsilon`; `q` independent runs are within `2*q*T*epsilon`. Public PC/phase changes may change the reference law. Correlations within a run are retained.
- [NoisyTrace.history_trace_bound](masking/noisy_trace.v): if the two next-observation kernels have TV distance at most `epsilon` from each other at every shared observation history, complete traces are within `T*epsilon`, or `q*T*epsilon` for independent repeated runs. This rule retains distributional uncertainty instead of fixing every share. Connecting these kernels to the actual interpreter and proving the history-conditioned premise remain separate obligations.

Always cap the bounds at 1. Fix total noise `N` when comparing share counts: choose `e=N-n` for a bit or `e=N-w*n` for a word, only when the subtraction is nonnegative. Increasing shares while holding `e` fixed also increases noise. The fixed-noise regression compares certified bounds for two shares and four shares with eight noise bits in both cases; it does not prove monotonicity of the exact distances.

These Boolean XOR encodings are not the prime-field arithmetic implementation. A 255-bit snapshot theorem is not a Curve25519 algorithm theorem. The pointwise full-trace premise fixes persistent shares, whereas the snapshot bound averages over fresh shares: the latter cannot simply discharge the former. The arithmetic whole-bank development below retains mask uncertainty conditioned on observation history. No Gaussian/physical calibration or glitch model is claimed.

The checkpoint theorem remains separate from the actual stored-state execution theorem below; it cannot substitute for intermediate-observation coverage.

## Decisions and Remaining Work

1. Preserve the valid masking checkpoint result; it does not satisfy the selected aggregate-register-HW contract. The current multiplication has checked counterexamples under stronger observations.
2. Complementary storage assumes equally weighted bits and atomic paired updates at tick boundaries. Default all-zero storage is not a valid protected initial state. Combinational intermediates, glitches, transition/HD leakage, CPU registers, and external interfaces are not covered.
3. Preserve the checked masked-controller bound under the common noisy channel. Do not substitute final-Y secrecy for aggregate-HW protection or assume that a probing theorem applies to this channel without a reduction.
4. The dual controller's RTL generation-and-validation milestone uses an explicit trusted printer/clock-wrapper/simulator boundary. Formal downstream equivalence and synthesis-preservation checks are optional assurance extensions, not additional requirements for that milestone. CPU/MMIO marshaling and full-program correspondence remain separate future integration work. Masking still requires generated-RTL validation at the certified share count; small-instance tests do not discharge that requirement.

## Agreed Roadmap

1. Complete the random-masking exploration under the common quantitative noisy-leakage contract above.
2. Implement complete Montgomery-ladder circuits in Quartz, then relate generated RTL to the checked model. Prove functional correctness and leakage bounds separately for dual-storage and masked implementations under the same channel and budget.
3. Build the processor version after discussing public/secret classification. Classification must cover register updates, memory, addresses, control, and intermediate storage, not only an initial register list.
4. Prove an ISA-contract theorem for every compliant program. Programs that expose secrets through public control or unapproved outputs must be rejected or fall outside the theorem. Intended output release needs an explicit policy.
5. Instantiate the processor theorem for Montgomery ladder and further crypto programs, then automate contract checking and proof composition. The generic theorem supplies leakage protection; each algorithm still needs its own functional specification.
